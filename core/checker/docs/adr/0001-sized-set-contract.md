# Preserve the declared maximum size of sets

Static Semantics follows [#70](https://github.com/pixelscortex/aureline-orm/issues/70): `array<T, N>` has exactly `N` members, while `set<T, N>` has at most `N` distinct members. The [official set documentation](https://surrealdb.com/docs/reference/query-language/language-primitives/data-types/sets) describes the maximum-size contract, but the tagged [SurrealDB v3.2.0 coercion implementation](https://github.com/surrealdb/surrealdb/blob/v3.2.0/surrealdb/core/src/val/value/convert/coerce.rs#L842-L861) and [v3.3.0-beta.3 implementation](https://github.com/surrealdb/surrealdb/blob/v3.3.0-beta.3/surrealdb/expr/src/val/value/convert/coerce.rs#L855-L875) instead require equality after deduplication.

The Checked Program preserves Aureline's selected maximum-size contract rather than silently changing it to match those releases. This is a known compatibility gap, not a claim that those servers enforce the checked constraint. Downstream migration generation must resolve target compatibility before emitting sized-set DDL; that policy belongs to the deferred generation work in #51. This slice adds no database execution or version configuration.
