# Enforce maximum sized sets with assertions on SurrealDB 3.2.0

Migration generation targets SurrealDB **3.2.0**, whose native sized-set coercion requires equality after deduplication. Aureline's Checked Program instead promises at most N distinct members. Generation therefore emits native **unsized** `set<T>` for element validation and deduplication, followed by an `ASSERT set::len($value) <= N`. The snapshot retains `set<T, N>` as the semantic contract. It is not target DDL.

Bounds nested in arrays and sets are checked with `array::all` and `set::all`; tuple members use indexed predicates. Options guard absence. A union with bounded-set descendants and more than one present alternative blocks generation: removing bounds can change which alternatives overlap, and a bound without a proven branch guard is unsound. This includes unions nested inside collections. No migration or snapshot is returned on rejection. General union support must prove both branch selection and coercion before lifting this restriction. Sized-set bounds above `i64::MAX` also block because the target parses expression integers as signed 64-bit values; array type lengths use its separate unsigned parser and retain the full `u64` range.

Pinned primary-source verification (no database was executed):

- [`coerce_to_set_kind` and `coerce_to_set_kind_len`](https://github.com/surrealdb/surrealdb/blob/v3.2.0/surrealdb/core/src/val/value/convert/coerce.rs#L876-L909): unsized coercion validates elements and collects a distinct set; sized coercion compares the resulting length for equality.
- [`process_type_clause` before `process_assert_clause`](https://github.com/surrealdb/surrealdb/blob/v3.2.0/surrealdb/core/src/doc/field.rs#L320-L341), and [assertion context](https://github.com/surrealdb/surrealdb/blob/v3.2.0/surrealdb/core/src/doc/field.rs#L623-L670): `$value` is the coerced field value; optional absence is permitted.
- [`set::len` and `set::all`](https://github.com/surrealdb/surrealdb/blob/v3.2.0/surrealdb/core/src/fnc/set.rs#L79-L121), [`array::all`](https://github.com/surrealdb/surrealdb/blob/v3.2.0/surrealdb/core/src/fnc/array.rs#L52-L79): length observes distinct members, and universal predicates accept empty collections.
- [Tuple validation](https://github.com/surrealdb/surrealdb/blob/v3.2.0/surrealdb/core/src/expr/kind.rs#L846-L862) preserves exact member order and arity. Array exact lengths retain native `array<T, N>` syntax.
- [Expression integer parsing](https://github.com/surrealdb/surrealdb/blob/v3.2.0/surrealdb/core/src/syn/lexer/compound/number.rs#L24-L57) rejects bounds beyond `i64::MAX`; [array type lengths](https://github.com/surrealdb/surrealdb/blob/v3.2.0/surrealdb/core/src/syn/parser/kind.rs#L185-L192) use `u64`.
- [`ALTER FIELD`](https://github.com/surrealdb/surrealdb/blob/v3.2.0/surrealdb/core/src/sql/statements/alter/field.rs) supports `TYPE`, `ASSERT`, and `DROP ASSERT`; removing a bound must also remove its generated assertion.

For the later database acceptance work in #44, use native set values (for example `<set>[1, 1, 2]`), not arrays: this target distinguishes the runtime types. For `set<int, 2>`, empty, one distinct member, and two distinct members pass; three distinct members fail; duplicate input counts after deduplication. A zero bound accepts only the empty set. Repeat these cases inside arrays, sets, options, and tuples. Generation tests verify the emitted constraints and generation-blocking cases; they do not claim execution-based verification of the target.

SurrealDB also [creates wildcard field definitions recursively](https://github.com/surrealdb/surrealdb/blob/v3.2.0/surrealdb/core/src/expr/statements/define/field.rs#L313-L376) for collection inner kinds when defining a parent. Its `ALTER FIELD` and `REMOVE FIELD` statements touch only the named definition. Planning therefore derives the same wildcard paths from the old and new contracts: existing paths are altered, obsolete paths are removed deepest first, and new paths are defined as `any` then altered to their final type. That two-statement addition prevents `DEFINE` from unexpectedly creating more descendants. The parent owns all sized-set assertions; implicit child kinds have native unbounded sets. Dropping a declared collection removes its derived children as well. These are deterministic target consequences of model types, not source declarations or additional snapshot entities.
