## Maintain affected records without widening scope

**Context:** A change makes the upper bound exclusive. A nearby comment still says it is inclusive, while another file contains an unrelated low-information comment.

**Don't:** Preserve the stale record or start a repository-wide cleanup.

```ts
// Include events at the cutoff.
return event.timestamp < cutoff;
```

**Do:** Rewrite or remove the affected record so it describes current meaning, then stop at the semantic boundary of the task.

```ts
// Exclude events at the cutoff so adjacent windows cannot process one event twice.
return event.timestamp < cutoff;
```

**Why:** Git retains chronology; the working tree must communicate the current decision, and narrow scope keeps an ordinary change reviewable.

**Exception:** Broaden cleanup only when the task explicitly targets comment quality across that wider scope.

## Keep generated reasoning in the source

**Context:** A build step emits an error-code module and a required generated-file notice. One error constant needs a caller-facing retry warning owned by the generator's definition data.

**Don't:** Hand-edit the generated file with reasoning that disappears on the next run.

```ts
// Code generated by Aureline. DO NOT EDIT.
// Retry only after refreshing the authentication token.
export const TOKEN_EXPIRED = "TOKEN_EXPIRED";
```

**Do:** Preserve the required notice and place the warning in the generator input or template that owns the output.

```ts
{
  name: "TOKEN_EXPIRED",
  documentation: "Retry only after refreshing the authentication token.",
}
```

After regeneration, retain the generated notice alongside the emitted documentation:

```ts
// Code generated by Aureline. DO NOT EDIT.
/** Retry only after refreshing the authentication token. */
export const TOKEN_EXPIRED = "TOKEN_EXPIRED";
```

**Why:** Regeneration preserves the design record and keeps one authoritative source for it.

**Exception:** Retain comments that the generator, language, or framework requires in generated output.
